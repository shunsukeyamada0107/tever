# Your Manager（BAR TEVER 店舗管理アプリ）

複数のバー・スナック等を運営する事業者向けの、店舗管理Webアプリ。
Next.js 14 (App Router) + TypeScript + Tailwind CSS + Supabase (Postgres / Auth) 構成。

## 全体構成

- **店舗（stores）**がテナントの単位。店舗ごとにログインアカウント（`store_members`）を持つ
- 複数店舗をまとめて運営する事業者向けに、**組織（organizations）**という上位単位もある
  （本部アカウント1つで配下の全店舗の実績を横断で見られる）
- 運営（開発者）専用の管理画面 `/admin` から、店舗・組織の作成やアカウント発行を行う

```
/login          … 全アカウント共通のログイン画面
/dashboard/*    … 店舗アカウント用（オーナー・スタッフ）
/org            … 組織アカウント用（本部・複数店舗の統括担当）
/admin          … 運営専用（店舗・組織の作成、アカウント発行、代理ログイン）
```

ログイン後の行き先は、そのアカウントが店舗に属していれば`/dashboard`、
組織に属していれば`/org`に自動で振り分けられる。

## 店舗アカウントの機能（`/dashboard`）

### 伝票（POS、`/dashboard`）
- お客様・卓ごとの伝票（タブ）を作成・切り替え
- メニューからワンタップで追加、自由入力での追加も可能
- 品目ごとに担当スタッフを割り当て（歩合給の対象。伝票全体の担当とは別に上書き可）
- 割引（%指定 / 金額直接入力）
- 小計・消費税・合計をリアルタイム表示（合計は¥100単位に切り上げ）
- 現金／カードで会計 → **会計ボタンを押すと金額入り確認ダイアログが出る**（誤タップ防止）
- 会計の取り消し、伝票削除（削除は確認ダイアログあり）
- 飲み放題コースの残り時間表示

### 経費（`/dashboard/expenses`）
- 経費の入力（カテゴリ・品名・金額、レシート画像添付）
- 時給制スタッフの出退勤入力（出勤・退勤時刻）

### 集計（`/dashboard/report`）
- 本日／今月のサマリー（売上・経費・人件費・粗利を別建てで表示）
- スタッフ別の人件費内訳（時給分・歩合給分・担当売上）
- 売上・原価の推移グラフ、ルールベースの「気づき」表示
- LINE報告用テキストの自動生成（コピーボタン付き）
- 過去日・未来日の遡り閲覧（営業日切替時刻をまたぐ日付計算に対応）

### 設定（`/dashboard/settings`）
- 店舗情報（税率、営業日切替時刻、ブランドカラー、テーマ、金庫元金など）
- 歩合給の方式切り替え：
  - **simple**：会計額に対して一律%
  - **drink_back**：担当売上バック％＋キャストドリンク1杯ごとの固定バック額
- スタッフの追加・時給設定・歩合対象外フラグ
- メニューの名称・価格・並び順編集、キャストドリンク（🍾）指定

## 組織アカウントの機能（`/org`）

複数店舗をまとめて見たい事業者（チェーン展開など）向けの、読み取り専用ダッシュボード。

- **いまの状況（ライブ）**：15秒ごとに自動更新。今まさに入店中の組数・人数、
  会計前（未確定）の売上合計を、全店合計＋店舗別に表示。「更新：◯秒前」表示付き
- 本日・今月の売上／経費を、全店合計＋店舗別に表示
- **店舗カードをタップすると、その店舗のオーナーとしてログインし直せる**
  （自分の組織に属する店舗にしか入れないよう制限済み）

## 運営専用機能（`/admin`）

- 店舗の作成・削除、プラン状態（トライアル／有料／停止）の切り替え
- 任意の店舗に「入る」（オーナーとして代理ログイン）
- 組織の作成、既存店舗の組織への割り当て、組織用ログインアカウントの発行

## データ・権限まわり

- Supabase Row Level Security（RLS）で、店舗間・組織間のデータ漏洩を防止
  - 店舗アカウント：自分の`store_members`に紐づく店舗のデータのみ
  - 組織アカウント：自分の`organization_members`に紐づく組織配下の店舗のデータのみ（読み取りのみ）
- `schema.sql`（リポジトリルート）が最新のテーブル・RLS定義。ただし本番DBへの反映は
  Supabase SQL Editorで手動実行（マイグレーションツール未導入）なので、変更時は
  schema.sqlと実際のDBが一致しているか都度確認すること
- 自動テスト（Vitest, `lib/types.test.ts`）で金額計算・日付計算のロジックを保護

## セットアップ手順

1. `npm install`
2. `.env.local.example` を `.env.local` にコピーし、Supabaseプロジェクトの
   URL・anonキー・service roleキー・運営用メールアドレスを設定
3. `npm run dev` で `http://localhost:3000` を確認
4. 動作確認後、`git push` すると Vercel が自動でデプロイ（本番URL: `tever-nu.vercel.app`）

## コード変更時の確認手順

1. `npx tsc --noEmit`（型チェック）
2. `npx vitest run`（テスト）
3. devサーバーを止めて `rm -rf .next && npm run build`（ビルド確認）
4. devサーバーを再起動して動作確認
5. ユーザーが実機で確認 → 問題なければ `git commit` → `git push`（Vercelが自動デプロイ）
